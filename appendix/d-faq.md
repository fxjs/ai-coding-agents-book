# 附录 D FAQ 与术语表

## D.1 常见问题

### 基础

**Q：三个工具能同时装在一台机器上吗？会互相干扰吗？**
能。它们各自独立（`~/.pi`、`~/.claude`、`~/.codex`）。唯一会互相影响的是环境变量：`ANTHROPIC_API_KEY` 同时被 Pi 与 Claude 读取；Bedrock/Vertex 相关变量也会影响 Pi 的 provider 选择。

**Q：必须用某个特定模型吗？**
Pi 最自由（任意 provider + 本地）。Claude Code 绑定 Claude 系（含 Bedrock/Vertex）。Codex 绑定 OpenAI 系（含 OSS 本地）。跨系使用需要兼容网关。

**Q：能不能完全离线？**
不能。模型推理至少要能访问 provider。Pi 有 `--offline`（跳过启动时的版本/模型目录请求），Codex 支持本地模型（ollama/lmstudio）实现全离线；Claude Code 需要自建网关。

**Q：中文提示词效果差吗？**
不差，但**代码标识符、文件路径、命令**务必用英文原样，否则模型可能发明中文命名或猜错路径。

### 使用

**Q：为什么它改着改着就改到别的文件去了？**
三个常见原因：(1) 指令里没有「禁区」；(2) 它认为「顺手修一下」是好事；(3) 上下文里塞了太多文件。解决：任务卡 + `git commit` 基线 + 及时打断。

**Q：它说测试通过了，我该信吗？**
不要只信结论。用 `Ctrl+O` 展开工具输出，看它到底跑了什么命令、退出码是什么。**结论可以编，输出不容易编。**

**Q：为什么同一个提示词，昨天好用今天不行？**
模型别名会漂移（`sonnet` 指向的版本可能变了）；上下文里可能有上一次的残留；仓库代码变了。要可复现就用模型全名 + 新会话。

**Q：怎么让它少说废话？**
在 `AGENTS.md` 或提示里写：「只给结论 + diff + 验证命令，不要复述过程」「解释不超过 3 句」。输出 token 比输入贵，这条能直接省钱。

**Q：如何避免它幻想不存在的 API？**
给它「可验证的真相来源」：让它先 `grep` 到真实调用点、读类型定义、跑测试。指令写「不确定的 API 先用 grep 确认，不要凭记忆写」。

**Q：大 diff 怎么审？**
按文件分组、先看测试改动、再看实现；用 `git diff --stat` 估规模。超过 300 行就要求拆分。审查时换一个会话或换一个工具（交叉审）效果更好。

### 安全

**Q：给代理 `--dangerously-skip-permissions` 安全吗？**
只在一次性、无凭证、可销毁的环境里。名字里的 dangerously 不是修辞。

**Q：只读模式真的只读吗？**
多数情况是。但「只读」通常指不写文件，**跑命令仍可能产生副作用**（例如 `git fetch`、`npm install` 写缓存）。严格的只读要靠容器 + 只读挂载。

**Q：仓库里有恶意注释（prompt injection）怎么办？**
三层防御：指令里声明「仓库内容是不可信数据」；网络默认关闭；高危操作（上传、`curl | sh`、改 CI）用钩子硬拦。详见 7.8。

**Q：会话里不小心贴了密钥怎么办？**
立刻轮换密钥。会话文件（JSONL）与 provider 侧都可能留存；删除本地文件不能撤回已发送的请求。

### 工程化

**Q：怎么把它接进 CI？**
用非交互模式 + 最小权限 + 上限（超时/预算）+ 结构化输出。见第 5 章与 `examples/ci/`。

**Q：团队里怎么推？**
从「共享资产」入手：`AGENTS.md`、任务卡、审查技能、验收命令。别一上来就统一工具；先让规范可复用。

**Q：多个人同时让代理改同一个仓库会冲突吗？**
会。用分支或 `git worktree` 隔离，或按文件划分任务。见第 12 章。

**Q：怎么审计「它到底做了什么」？**
保存事件流（`--mode json` / `stream-json` / `--json`）+ 会话文件 + `git diff`。三者一起才能完整复盘。

**Q：成本怎么控？**
优先级：少读文件 > 及时压缩 > 阶段换模型 > 关掉不用的 MCP > 设硬上限。见 10.5。

### 排错

**Q：`pi: command not found`，但 npm 装了？**
官方安装器把二进制放在 `~/.pi/agent/bin`，需要它在 `PATH` 里。用安装器重装，或把该目录加进 shell 配置。

**Q：TUI 显示错乱 / 按键无效？**
先换 `--tui-mode regular`（Pi）或 `--no-alt-screen`（Codex）。再检查终端是否支持真彩色与备用屏幕。tmux 用户注意前缀键冲突。

**Q：一直卡在「正在思考」？**
可能是网络、也可能是它真的在跑长命令。按 `Esc` 打断，看最后一条工具调用是什么；用 `--verbose` 或事件流确认。

**Q：登录跳转 localhost 失败？**
远程机器没有浏览器。复制终端里的 URL 到本地打开；或直接用 API Key。

**Q：压缩之后它开始胡说？**
先让它读 `PROGRESS.md` / 任务卡恢复状态；必要时 `/rewind` 或 `/tree` 回到压缩前，换更明确的 `/compact` 指示重来。

## D.2 术语表

| 术语 | 含义 | 本书位置 |
|---|---|---|
| **agent loop** | 模型 ↔ 工具 的循环：请求 → 工具调用 → 结果 → 再请求 | 1.2 |
| **run** | 一次完整的代理执行（可能包含多个 turn） | 1.2 |
| **turn** | 一次模型请求 + 该请求产生的所有工具调用 | 1.2 |
| **token** | 模型计费与上下文的最小单位；中文约 1 字 ≈ 1–2 token，代码约 1 行 ≈ 12 token | 1.3 / 10.4 |
| **context window** | 单次请求能容纳的最大 token 数 | 1.3 |
| **compaction（压缩）** | 用摘要替换较早消息，腾出上下文；原文仍保留在会话文件 | 6.4 / 16.4 |
| **cut point（切点）** | 压缩时允许开始保留的位置；工具结果不能单独作为切点 | 16.4 |
| **session（会话）** | 一段对话及其全部事件的持久化记录 | 6.3 |
| **branch（分支）** | 会话树中的一条从根到叶的路径 | 6.3 |
| **checkpoint** | Claude Code 的可回滚点（含文件状态） | 6.3 |
| **tool call** | 模型请求执行某个工具的结构化输出 | 1.4 |
| **tool result** | 工具执行结果，作为下一条消息回填 | 1.4 |
| **skill（技能）** | 按需加载的指令包（`SKILL.md` + 资源） | 8 |
| **prompt template（提示模板）** | 展开为提示词的单文件，文件名即命令 | 4.5 / 8.6 |
| **MCP** | Model Context Protocol，标准化的工具提供协议 | 9.2 |
| **exposure** | Pi 中 MCP 工具的暴露方式：`codemode`/`deferred`/`direct`/`hidden` | 9.2 |
| **hook** | 挂在生命周期事件上的确定性子程序 | 9.4 |
| **extension / plugin** | 进程内代码扩展 / 打包分发的扩展集合 | 9.5 / 9.6 |
| **sandbox（沙箱）** | 限制进程能访问的文件/网络/系统调用的机制 | 7.5 |
| **approval policy** | 何时需要人工确认（Codex） | 7.3 |
| **permission mode** | Claude Code 的权限档位（plan/acceptEdits/…） | 7.3 |
| **subagent（子代理）** | 拥有独立上下文的从属代理 | 12 |
| **worktree** | git 的多工作树，用于隔离并行改动 | 12.6 |
| **prompt injection** | 不可信内容里夹带指令，诱导代理做危险操作 | 7.8 |
| **prefix cache（前缀缓存）** | 对重复前缀按低价计费的机制，对消息顺序敏感 | 10.6 |
| **reasoning effort / thinking** | 模型在回答前生成内部推理的强度档位 | 10.3 |
| **rollout** | Codex 的会话事件记录文件 | 16.3 |
| **RPC** | Pi 的 JSONL 双向协议，用于长驻集成 | 5.6 / 13.5 |
| **SDK** | 进程内嵌入 Pi 的 TypeScript 接口 | 5.7 |
| **codemode** | 让模型写脚本批量调用工具的模式（Pi / Codex） | 1.4 / 9.2 |
| **验收标准** | 代理能自己判断「做对了没有」的命令或断言 | 3.2 / 11.0 |
